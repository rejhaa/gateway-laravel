#### What the research settled

- **laravel/mcp 1.2.1 covers the July protocol and the card.** It answers 2026-07-28 and the three older versions with no configuration, and it is stateless. It ships `AppResource`, `#[RendersApp]` and a CSP builder for MCP Apps cards.
- **The package never validates tool input against the schema**, so each tool validates its own input. With `APP_DEBUG=true` a tool exception is shown to the agent and not logged, so the gateway needs its own error wrapper around every tool.
- **claude.ai renders the card and Claude Code does not.** Claude Desktop has no build for Arch. claude.ai connects from Anthropic's servers, so the gateway needs a public HTTPS tunnel, and the card's buttons also call the gateway from your browser through that tunnel.
- **Odoo's JSON-2 API has no compare-and-set.** The gateway can re-read a record right before writing and refuse if it changed, which leaves a gap of a few milliseconds.
- **The old gateway had no duplicate protection**, and its commit and wait tools existed only because approval and writing were separate steps. Your new flow removes both problems.
- **No case is loaded in Odoo right now.** `bin/odoo seed cases/demo/demo-mailbox` has to run before the demo.

#### The three tiers in the smaller version

**Applied at once by a rule.** A write to a line of a confirmed purchase order that touches only `date_planned`, `x_confirmed_qty` and `x_confirmed_date`, passes every shared condition, and fits one of the two rules:

- `confirmation-as-ordered` records the confirmed quantity and date when the quantity equals the ordered quantity and the date equals the current planned date.
- `planned-date-under-cap` moves the planned date when the slip from the requested date is under 14 days and no manufacturing order waits on the line.

**Waits for Riku.** Two kinds of proposal wait:

- Every dispute on a vendor bill (`x_dispute` = `disputed` with its note).
- Any write of the three line fields that fails a condition. The failures are a partial quantity, a slip of 14 days or more, a line with no requested date, a waiting manufacturing order, an order not in state `purchase`, a quote that does not name the product or state the value, an ambiguous date, a document without a text layer, a message that does not name the order, a newer uncited message that names the order, the same message already applied to the line by rule, and the rule tier switched off.

**Denied by policy.** Four kinds of proposal are denied:

- A write to a field the agent never writes, which covers ordered quantity, price, product, requested date, order or line state, the order's lines, stock move quantities and manufacturing order dates. The denial cites the POL section.
- A write of `x_dispute` to anything other than `disputed`, which would lift or settle a dispute.
- Any field or model on neither list.
- Any method call, since this version has none.

3. **A message that names several orders.** A statement listing two orders for the same product lets one order's row pass by rule on the other order's line. The fix is to send the proposal to Riku when the message names more than one order of that supplier. I recommend adding it.
