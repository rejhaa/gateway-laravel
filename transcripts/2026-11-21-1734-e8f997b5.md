## Prompt 4 (19:17)

> what should be done about the keys?

### Claude

Nothing needs doing for the demo. Keeping them out of git is the right state, and here is how each one behaves.

- **Passport keys** (`storage/oauth-private.key`, `storage/oauth-public.key`). They sign Claude's access tokens. Each machine generates its own, and `composer setup` runs `php artisan passport:keys` when the private key is missing, so a fresh clone gets a pair without a manual step. Do not delete or regenerate them between demo runs, because every issued token stops working and the connector in claude.ai has to be authorized again. `gateway:reset` leaves them alone.
- **`APP_KEY`** in `.env`. It signs the card tokens and the session cookies. Changing it expires every open card and signs Riku out, which is harmless.
- **Odoo API keys** (`odoo/data/`, also not in git). Every `bin/odoo seed` replaces them, and the gateway reads the file on each call, so they need no handling.

If the gateway is ever deployed somewhere other than your machine, pass the Passport pair through the environment (`PASSPORT_PRIVATE_KEY` and `PASSPORT_PUBLIC_KEY`) instead of files, so a redeploy does not mint a new pair and disconnect Claude.
