#### The main choices

- **Stack.** Laravel 13 on PHP 8.5, served by FrankenPHP in classic mode, with the gateway's own data in SQLite as in the original.
- **MCP.** The first-party `laravel/mcp` 1.2 with Passport for OAuth. It has MCP Apps support for the approval card and generator tools for the 15-minute wait.
- **Odoo.** The official `odoo:20.0-20261112` image with Postgres, both in `docker compose`. The original makes every customization in `inbound-seed.py` through the ORM, so the design copies that script and `inbound-case.py` unchanged instead of writing an addon.
- **First start and reset.** A one-shot `odoo-init` service installs the modules and seeds on first start, which takes a few minutes once. `make reset` reloads the seed, the demo case, the mail and clears the plans in about 10 seconds, estimated from the original's load times. `make fresh` drops the volumes.
- **Mail.** The gateway reads `.eml` files from `storage/app/mailbox` on each call, and handled state is a database row. I added two small gateway routes that show a message and serve an attachment, because the approval page links each cited passage to its document.
- **Documents.** Poppler (`pdftotext -bbox`, `pdftoppm`) replaces pdf.js, with the original's line grouping ported.

#### Where it differs from the original

- **Scopes.** `laravel/mcp` supports only one OAuth scope. The consent page still shows `odoo:read` and `odoo:write` as ticked boxes, but the grant is stored per user and client, not in the token.
- **Sessions.** The package looks stateless, which I inferred from its release notes and did not confirm in its source. The card secret becomes a signed token and the live wait becomes a heartbeat row.
- **Elicitation.** It is left out. The package has it only on a branch, and the inbound run does not use it.
- **Line labels.** Poppler can split lines differently from pdf.js, so labels in the original's recorded runs will not match.
