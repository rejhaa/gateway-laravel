#### Odoo in containers

- `compose.yaml` has three services: `db` (postgres:18), `odoo-init` and `odoo`.
- The image is the official `odoo:20.0-20261112`, pinned. The source project ran the 20261010 nightly from source, and the seed's own checks will show if the newer build behaves differently. I add a thin Dockerfile only if the seed needs a Python package the image lacks.
- `odoo-init` runs once per fresh volume. It creates the `inbound` database with `purchase, stock, mrp, sale_management, account, purchase_stock, purchase_mrp` and no demo data, then runs the base seed. `odoo` starts only after it succeeds.
- Odoo listens on `localhost:8070` (`ODOO_PORT` in `.env` changes it). Postgres publishes no host port, so it cannot collide with your local Postgres.
- `bin/odoo-seed` reseeds the base, and `bin/odoo-seed cases/demo/demo-mailbox` loads a case on top. Both run `odoo shell` in a one-off container while the server keeps running.
- The seed writes the API keys and the case map to `odoo/data/` on the host (git-ignored), so the Laravel app can read them later.

On a new machine the demo is `cp .env.example .env && docker compose up -d`.
